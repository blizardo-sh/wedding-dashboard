# Место для нас

Дашборд для совместного выбора дома на свадьбу: таблица, карточки с фотографиями, сравнение 2–5 домов, настройка дат, гостей и услуг, фильтры, заметки и история уточнений.

## Запуск на своём компьютере

Нужны Node.js 24 и pnpm 11.25.0. Из этой папки:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Откройте адрес, который напечатает Vite. По умолчанию это `http://127.0.0.1:5173/`. Сервер слушает только loopback. Локальный режим использует каталог из `../.private/dashboard/`; другой путь задаётся через `WEDDING_DATA_DIR`. Заметки сохраняются только в этом браузере, с честной отметкой локального режима. Это режим подготовки, без Google-входа и синхронизации между устройствами.

Продакшен-сборка не содержит локального каталога и не умеет отдавать его. Без подключения Firebase она показывает экран настройки.

## Импорт исходных файлов

Исходные XLSX и сохранённые карточки не изменяются. Нужен Python с openpyxl:

```sh
python3 scripts/import-data.py \
  --base /path/to/collection-500 \
  --cian /path/to/Wedding_Cian_21-22_Feb_2027.xlsx \
  --workspace /path/to/original-workspace \
  --output ../.private/dashboard
pnpm data:export
```

Импорт сохраняет тексты, хеши, ссылки, цитаты, фотографии, отдельные предложения источников и стабильные идентификаторы групп домов. `catalog.json`, `details/*.json`, `cloud-import.json` и отчёты проверки находятся только в закрытой папке. Не помещайте её в `public/`, `dist/` или Git.

Связи по коду объекта и идентичному тексту предварительные. Возможные дубли можно вручную объединить и разделить. Исходные решения не удаляются. Старые ограничения по бюджету и числу мест не наследуются; явные другие регионы доступны отдельным переключателем.

## Как считается цена

По умолчанию: 21–22 февраля 2027 года, 35 человек всего, из них 20 ночующих. Даты, 1–2 ночи, гости по дням, дети и услуги настраиваются. Дополнительные спальные места учитываются наравне с кроватями.

Переключатель «Полная стоимость / Стоимость в объявлении» меняет цену в таблице, карточках и сравнении, а также сортировку, бюджет и экспорт. Полный расчёт учитывает даты, гостей, обязательные платежи и выбранные услуги; цена объявления сохраняется без пересчёта. При отсутствии тарифа аренды полная стоимость показывается как «Не рассчитана», без подстановки цены объявления. Обязательная уборка включается всегда; уборка по выбору подключается в услугах, если это допускает предложение. Выбор режима сохраняется на устройстве и не меняет сценарий или ответы владельцев.

Смета строится целиком по одному объявлению. Складываются аренда на применимые дни, обязательные расходы и выбранные услуги. Залог и предоплата показываются отдельно. Часы и сеансы услуг задаются за весь заезд. Если ежедневный бесплатный лимит требует распределения по ночам, расчёт остаётся неполным до уточнения.

Неизвестная уборка или доплата не становится нулём. Без однозначного тарифа на даты показывается цена объявления с отметкой «не смета». Неполная сумма не считается подтверждением попадания в бюджет. Приоритет выбора источника: подтверждённая цена для точного сценария, полный ориентир, частичный расчёт; затем цена. Можно выбрать источник вручную.

Ручные ответы хранятся отдельно от импорта, по объявлению. Ответ о полной цене действует только для точного сценария. Удобства имеют состояния «да / нет / неизвестно»; сезонность бассейна и включение услуги в стоимость учитываются отдельно.

## Закрытый доступ через Firebase Spark

1. Войти в Firebase CLI: `pnpm exec firebase login`. Коды входа вводятся в терминале, не в чат и не в Git.
2. Создать проект без подключения биллинга, зарегистрировать Web App и создать Firestore в production mode. В Authentication включить Google и добавить домен будущего сайта в Authorized domains.
3. Выполнить `pnpm exec firebase deploy --only firestore --project PROJECT_ID` для правил и индексов.
4. **До первого входа** доверенным администратором создать документы `members/{email}` для владельца и участников: `role: "owner"` или `"editor"`, `active: true`. Действительные адреса берутся из приватной конфигурации и не публикуются. Первому вошедшему права автоматически не выдаются.
5. Скопировать публичную конфигурацию Web App в `public/firebase-config.json` по примеру. Сервисные ключи и OAuth refresh tokens здесь не используются.
6. Войти владельцем и загрузить `cloud-import.json` через «Участники и импорт». Сначала загружается новая версия; переключение каталога происходит в конце. Ручные ответы, заметки и история не перезаписываются.

Все приглашённые могут редактировать выбор и уточнения. Только владелец управляет доступом и импортом. Каждая правка транзакционно сопровождается неизменяемым событием с автором, временем, ревизией и итоговым состоянием. Правила отклоняют запись без соответствующего события. Сам вход через Google не открывает данные посторонним.

Фото загружаются по исходным URL с заглушкой при недоступности. Firebase Storage не требуется. Google Auth и Firestore работают в пределах бесплатных квот Spark; приложение не подключает платные услуги автоматически.

## Публикация на GitHub Pages

В отдельный публичный репозиторий отправляется только содержимое этой папки с учётом `.gitignore`. Данные и список участников туда не копируются.

В Settings → Pages выбрать GitHub Actions. Публичная конфигурация Firebase Web App хранится в `public/firebase-config.json`; она содержит идентификаторы проекта, без закрытых ключей. При необходимости её можно переопределить переменной Actions `FIREBASE_WEB_CONFIG`. Workflow проверяет исходники, тесты расчётов, правила в эмуляторе и сборку, затем публикует только `dist/`. Доступ к данным проверяет Firestore Rules независимо от публичности веб-конфигурации. Firebase Rules публикуются отдельно администратором; приватные ключи не нужны GitHub Actions.

## Проверки

```sh
pnpm test
pnpm test:data        # стандартный Python 3, проверка денежных форматов
pnpm test:security    # нужен Java 21+
pnpm check:public
pnpm build
```

Данные можно дополнительно проверить и подготовить для импорта командой `pnpm data:export`: сверяются уникальные ID, сохранность описаний по SHA-256, принадлежность цитат источнику, размеры документов и три сценария расчёта для каждого объявления. Это техническая проверка; доступность и итоговые тарифы на даты подтверждает владелец дома.

Официальные основания: [Google Auth](https://firebase.google.com/docs/auth/web/google-signin), [правила Firestore](https://firebase.google.com/docs/firestore/security/rules-conditions), [проверка правил](https://firebase.google.com/docs/firestore/security/test-rules-emulator), [GitHub Pages Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
